# Jira: Projects and Project Types

A **project** is the container for a team's work. Every issue, board, and report in Jira belongs to one project. When you create a project, you choose a project type, and that choice decides which tools you get.

## Jira's Main Project Types

- **Jira Software:** built for software and development teams. It offers Scrum boards, Kanban boards, backlogs, sprints, and releases.
- **Jira Work Management:** built for general business teams such as marketing, operations, or HR. It is simpler and uses lists and boards without sprints.
- **Jira Service Management:** built for IT and support teams that handle requests and incidents.

## Team-Managed vs. Company-Managed

- **Team-managed** projects are self-contained. The team configures its own workflow, fields, and board, which makes setup quick. Admins have less control over the whole site.
- **Company-managed** projects share configuration across many projects, such as workflows, issue types, and permissions. Admins control these centrally, which suits larger organizations.

## Scrum vs. Kanban Inside a Jira Software Project

- **Scrum** works in fixed time-boxes called sprints. The board shows the current sprint, and you plan work before each sprint starts.
- **Kanban** has no fixed sprints. Work flows continuously across columns, and the focus is on limiting work in progress.

Both templates use the same underlying issues. The difference is how work is planned and displayed.

## Key Idea

Choose the project type first, because it limits which features you can use later. Scrum or Kanban is a board choice inside a Jira Software project, not a separate product.
